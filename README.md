# 武汉理工大学南湖图书馆座位预约助手 🎓

跨平台（Linux / Windows / macOS）的武汉理工大学南湖图书馆抢座/选座脚本。通过 Playwright 在后台登录学校统一身份认证，支持按需求时长筛选座位。

## ✨ 特性

- **智能时长筛选**：支持设定“必须满足的时长”（例如要求至少预约 420 分钟或直接到晚上 22:00），如果不满足条件，脚本会持续监控刷新，直到有符合要求的座位释放。
- **自动登录**：脚本启动无头 Chromium，优先复用本地会话。需要重新认证时，自动填写学校账号和密码。
- **预约滑块验证**：按官网配置判断是否需要验证，使用 `captcha-recognizer` 在本机识别 Tianai 滑块，并由官网验证组件取得预约所需的 `capToken`。识别模型在首次需要时加载，同一任务复用。
- **本地 WebUI 与 CLI**：
  - **本地工作台**：在网页中设置预约条件、验证登录、查看任务进度和确认预约。
  - **交互式向导**：小白友好，直接运行脚本按回车即可完成配置。
  - **命令行参数**：适合极客和定时任务，一行命令直接起飞。
- **精细化控制**：支持指定楼层、开始时间、刷新频率、最大尝试次数，甚至支持避开特定“雷区”座位（内置屏蔽部分位置）。
- **确认模式**：支持找到座位后“自动秒抢”，或“弹窗手动确认”（防止乱占座被关小黑屋）。

## 🛠️ 依赖与安装

使用 uv 安装项目依赖和 Chromium：

```bash
uv sync
uv run playwright install chromium
```

复制 `.env.example` 为项目根目录的 `.env`，填写学校统一身份认证的账号和密码：

```dotenv
WHUT_USERNAME=你的学工号
WHUT_PASSWORD='你的统一身份认证密码'
```

也可以设置同名环境变量，环境变量优先。脚本按账号和 `--session` 分开保存会话。`.env` 和 `.whut-auth/` 包含登录凭据或会话数据，均已加入 Git 忽略列表。

先单独验证登录：

```bash
uv run python whut-seat.py --login-only
```

此命令取得预约系统 Token 后退出。统一身份认证要求验证码、短信或其他二次验证时，脚本会报告并结束本次运行；登录后的图书馆预约滑块由预约流程自动处理。

## 🚀 使用流程与运行模式

### 核心运行流程
无论使用哪种模式，脚本的整体运行流程如下：

1. **启动脚本**，按需指定日期、楼层和时长。
2. **后台登录**，脚本复用会话或通过无头 Chromium 登录，并等待预约系统返回 Token。
3. **查询和预约**，登录成功后脚本开始查询座位。找到符合条件的座位并完成必要的手动确认后，按官网配置处理预约滑块，再提交预约。中途可按 `Ctrl+C` 退出。

预约滑块使用本地模型，不向第三方识别服务上传验证码。识别会考虑图片显示缩放和滑块起始偏移，优先用透明滑块轮廓与模型分割区域对齐，轮廓不可靠时回退原识别；低置信度、普通验证失败或当前验证码超时时会更换图片，每轮最多两张。两张都未通过时，保留抢座任务，按刷新间隔继续查找座位和验证；无限模式会持续尝试，`--once` 和最大尝试次数仍生效。相邻验证码生成至少间隔 1.5 秒；首次风控预警后等待 3 秒，连续预警时等待 6 秒，验证成功后恢复普通间隔，并显示错误码和原因。明确限流、登录过期、模型或组件异常时仍停止任务。登录 Token 过期并重新认证后，会重新取得验证凭据。当前支持图书馆预约页面的 Tianai 拼图滑块，不处理学校统一身份认证的短信等二次验证。

验证组件的固定父容器位于视口原点，以匹配官网 SDK 的起始坐标计算方式，避免提交的按下坐标偏出滑块按钮。拖动使用变速曲线、轻微位置与时间扰动，并在空间允许时小幅越过后回拉。鼠标位置统一取可用整数像素，相邻位置未变化时只等待、不重复发送移动事件；最终落点取识别位置的最近可用像素；轨道末端会限制越过幅度。纵向移动保留 1.2–1.8 个显示像素的平滑幅度，叠加扰动后限制在 ±2 像素内，避免浏览器整数坐标把亚像素移动全部抹去；常规单次轨迹计划耗时约 1.3–1.9 秒，接近轨道末端时可能更短；验证码重试间隔不变。轨迹调整不能保证通过服务器行为校验，仍以服务器返回结果为准。

验证码等待按截止时间计算，已在本轮换图前消耗的等待不会在整轮结束后重复添加；验证所耗时间计入本轮刷新间隔。按下滑块后检查 SDK 记录的起点，坐标超出按钮时取消本次提交并换图。等待日志带有轮次，方便区分多轮重试。这些检查不能保证服务器永不触发风控。

### 本地 WebUI

安装并配置好上面的依赖与 `.env` 后，从项目目录启动：

```bash
uv run python -m webui
```

工作台只监听本机，默认打开 `http://127.0.0.1:8766/`。端口占用时会自动选择可用端口，以终端显示的地址为准。可用 `--port 8767` 指定端口，用 `--no-browser` 关闭自动打开页面。

- **座位预约**支持 CLI 的预约选项。勾选「预约前手动确认」后，可以确认或跳过候选座位。
- **配置管理**可以保存学校账号和网页预约默认值到 `.env`。已保存的密码不会回填到网页。保存后，预约表单立即载入默认值，重开工作台也会保留。
- **空闲时段**先列出座位，再查询可约时间。快速查询会先判定较大的时间区间，仅细分未确认的部分，并合并连续空闲段；查询预算限制了额外试探。今天只处理尚未过去的时段，精确查询保留逐座时间轴。停止或失败后可点击「继续查询」，最近两分钟内已完成的结果会从本地记录恢复，过期结果重新获取。记录按账号、会话、日期、楼层和查询方式隔离。开启「自动刷新」会复用浏览器，轮流更新各阅览室的时间段；精确查询则每次更新三个座位。刷新保留其余结果、筛选条件和页码，页面隐藏时暂停发起后续刷新，空闲浏览器在 90 秒后退出。批量查询维持至少 3 秒的请求间隔。快速查询可能遗漏不足半小时的短空档和边界部分。

也可以直接在 `.env` 中设置网页默认值，例如：

```dotenv
WHUT_FLOOR=7
WHUT_DATE=today
WHUT_START=09:30
WHUT_DURATION=120
WHUT_INTERVAL=3
WHUT_MAX_ATTEMPTS=0
WHUT_ONCE=false
WHUT_AUTO_CONFIRM=true
WHUT_SESSION=whut
```

网页预约日期用 `today` 或 `tomorrow`，留空使用当天。开始时间留空时，今天从最近可预约时段开始，明天从最早时段开始。时长 `0` 表示最长可用，负数表示到闭馆。尝试次数 `0` 表示持续查找。终端按 `Ctrl+C` 关闭工作台和当前任务。

### 🟢 模式一：交互式引导
最简单的使用方式，无需记忆参数。直接在终端运行：

```bash
uv run python whut-seat.py
```
运行后，脚本会一步步询问需要的配置。在任何问题处直接按回车，都会选择最常用的默认选项，例如今天、全部楼层、现在开始、最长时长、自动确认。

### 🔴 模式二：命令行直达
适合熟悉参数后一键运行，或者配合定时任务使用：

```bash
# 抢七楼，从现在开始，一直预约到晚上 22:00（-t -1），无限循环尝试
uv run python whut-seat.py -f 7 -t -1

# 抢六楼，预约 120 分钟，最多尝试 50 次后停止
uv run python whut-seat.py -f 6 -t 120 --max-attempts 50

# 指定日期，全部楼层，找到符合条件的座位后弹出提示让你输入 y 确认，不自动预约
uv run python whut-seat.py -d 2026-06-18 --no-auto-confirm
```

## ⚙️ 命令行参数说明

| 参数 | 缩写 | 默认值 | 说明 |
| :--- | :---: | :--- | :--- |
| `--floor` | `-f` | `0` (全部) | 楼层选项：`6` = 六楼，`7` = 七楼，其他数字 = 全部楼层 |
| `--date` | `-d` | 今天 | 预约日期，格式 `YYYY-MM-DD` |
| `--start` | `-s` | 自动最近 | 预约开始时间，格式 `HH:MM`。不填则自动对齐到下一个 30 分钟档 |
| `--duration` | `-t` | `0` (最长) | 预约时长（分钟）。**填负数（如 `-1`）表示一直预约到 22:00 闭馆** |
| `--interval` | | `3.0` | 刷新间隔（秒），每次请求会附带 ±1 秒的随机抖动防封 |
| `--max-attempts`| | `0` (无限) | 最大尝试次数，`0` 表示不限制，直到抢到或手动 `Ctrl+C` 退出 |
| `--no-auto-confirm`| | `False` | 关闭自动预约。找到符合条件的座位后，需在控制台输入 `y` 确认 |
| `--once` | | `False` | 仅尝试一次（相当于 `--max-attempts 1`） |
| `--session` | | `whut` | 登录会话缓存名称 |
| `--login-only` | | `False` | 只验证登录，取得 Token 后退出 |

## 💡 常见问题与注意事项

1. **黑名单机制**：频繁预约并退座会导致账号被图书馆系统拉入黑名单（暂停预约权限）。建议在测试时使用 `--no-auto-confirm` 参数，找到座位但不立刻预约。
2. **黑名单座位屏蔽**：脚本内硬编码跳过了部分用户反馈体验不佳的座位（如 001-005, 187-194）。如有需要，可直接修改脚本中的 `BLACKLIST` 集合。
3. **Token 过期**：预约接口提示已有未结束的预约时停止继续验证；明确报告 Token 过期时，脚本会重新认证一次，并用新 Token 重试该请求。
4. **网络超时警告**：后台筛选时会查验每个座位的精确空闲时间线，如果偶尔遇到部分请求超时，脚本会自动静默跳过该座位并进行下一轮刷新。
5. **重复查询间隔**：预约任务会关闭无头浏览器登录页自动发出的房间列表查询，由脚本发送一次，避免登录后立即重复访问。首次请求和不同接口不额外等待；同一路径重复请求保持至少 3.5 秒间隔，只等待不足的部分。Token 更新后也会关闭页面的重复预查询。服务器仍明确返回限流时，任务停止并显示具体接口。
